# 3D models

Everything the game renders is generated by the scripts in `tools/blender/` and
committed here, under `Generated/`. There is nothing to download:

```pwsh
pwsh ./tools/blender/build_all.ps1      # regenerate every model (needs Blender 5.x)
```

The `.glb` files are committed on purpose. Art that has to be fetched before the
game will look right is art that is missing on a fresh clone, and the whole point
of generating it from code is that a change to the generator produces a reviewable
diff.

## Generators

| Script | Owns |
|---|---|
| `build_vehicles.py` | the shared mesh/material kit, tanks, self-propelled guns, anti-air, the harvester, Κατιούσα, the electro prototype, the drone and the aircraft |
| `build_figures.py` | soldiers: infantry, commissar, robot infantry, mercenary, stealth reconnaissance |
| `build_buildings.py` | headquarters, factory, power plant, nuclear plant, design bureau |

`tools/blender/build_all.ps1` runs all of them in order. Each generator writes only
its own files, so they never conflict.

## Slots

`src/MiVic.Game/Data/ModelCatalog.cs` maps every (faction, role) pair to a file
here. At present all 51 slots are generated; `--inspect-models` reports
`failures=0 missing=0` when that is true.

## Materials and the faction paint mask

A vertex colour is a **material**, and its **alpha is the faction paint mask**: 255
means the owning faction's colour covers that surface, 0 means the material is
drawn exactly as authored. The shader blends between the two and shades the faction
colour by the material's own brightness, which is what lets a Σοβιετικοί tank be red
while keeping black rubber tracks, a gunmetal barrel and a light grey radar dish.

Practically: anything that should say *whose* it is gets a high mask, anything that
should say *what* it is gets a low one. The material table lives at the top of
`build_vehicles.py` and is shared by all three generators.

## Known limitations

- Models render in their **bind pose**. There is no skeleton and no skinning: the
  node hierarchy is animated instead, by name — see below.
- A missing or unreadable file is not an error: `ModelCatalog` falls back to
  procedural geometry so the game always runs.

## Part names are an animation contract

The renderer animates parts **by name**, so the generators are not free to rename
them at will:

| Name | Motion |
|---|---|
| `wheel_*` | rolls, at the rate its own radius implies for the distance travelled |
| `turret` | traverses to face the unit's current target |
| `radar*` | sweeps continuously |
| `Leg*`, `Shin*` | a stride; the shin bends behind the thigh on the forward swing |
| `Arm*` | swings against the leg on the same side |
| `Body`, `Head` | bob with the footfalls |

A part named `turret` that is not a turret is a bug rather than a style choice —
the Κατιούσα's cab was once named that, and the cab swung round to aim at the enemy.

## The old borrowed models

`tools/fetch-assets.ps1` still downloads a Quaternius set into `Soviet/`,
`Chinese/` and `Western/`, which is where the game's models used to come from. No
slot references them any more: they were under the
[Quaternius Asset License (QAL) v1.0](https://quaternius.com/license.html), which
forbids redistributing the assets as assets, so they could not be committed and the
game did not look right on a fresh clone until a script had been run. Every role now
has a generated model instead, and those are ours to commit.

The folders can be deleted; if the script is run again it will simply re-download
them. If MiVic is ever published with any of those files, they may ship **inside the
game build**, but must not be published as a standalone asset pack.

## Orientation

MiVic renders every unit facing **+X**. glTF models usually face **−Z**, so the
loader rotates a model whose longest horizontal axis is Z so that axis points at
+X. The generators author vehicles and figures facing **+Y** in Blender, which the
exporter turns into −Z, so the generated models need the half turn and the quarter
turn that `ModelCatalog` gives them via `GeneratedYaw` and `FigureYaw`.

To check any model, use the headless inspector — it loads models through the real
loader and reports their dimensions and part names:

```pwsh
./MiVic.Game.exe --inspect-models
```

A tank whose long axis is not X, or an infantry model that is not taller than it is
wide, is a sign of a wrong rotation.

## Reviewing a model

A model judged from a 1280×720 screenshot has been judged blind: a soldier is about
forty pixels tall in that frame. Render the model on its own instead, at size, and
crop to it.

```pwsh
$exe = "src/MiVic.Game/bin/Debug/net9.0/MiVic.Game.exe"

& $exe --viewer-model "Soviet/Tank" --viewer-shot tank.png `
       --viewer-distance 12 --viewer-pitch 32 --viewer-angle 45 --width 1920 --height 1080

pwsh tools/crop.ps1    -Path tank.png -Out close.png -X 600 -Y 220 -Width 760 -Height 660
pwsh tools/montage.ps1 -Out sheet.png -Paths a.png,b.png -Labels Soviet,Chinese -Columns 2
```

`--viewer-distance` is metres, `--viewer-pitch` is degrees above the horizon and
`--viewer-angle` is yaw in degrees (45 gives a three-quarter view; 90 is dead-on).
The fixtures need the project built first, and they are the only way to see a model
without playing the game.
